# 서술형 대비 (6문항 × 5분, AI·복붙 불가)

인지 축이 가장 중요하다고 Cofa Probe 담당자 두 명이 모두 말했고, 코파톤 실측에서는 참가자 전원이 이 축에서 가장 낮았다.
즉 **가장 많이 올릴 수 있는 곳**이다.

> 코파톤에서는 시스템이 문항마다 모범 답안을 미리 만들어 두고 대조했다(참가자 후기).
> Probe는 답변이 실제 구현과 일치하는지도 확인한다(공식 소개).
> 실제 응시에서 "어떤 알고리즘을 썼나", "데이터 입력부터 흐름을 통해 구조를 설명하라" 외에도 여러 유형이 나왔다.

## 공통 원칙

- **이름으로 말한다.** 파일명, 함수명, 데이터 형식, 실제 수치. "적절히 처리" 같은 말은 점수가 안 된다.
- **질문이 묻는 형식으로 답한다.** 흐름을 물으면 순서로, 이유를 물으면 대안과 비교로, 한계를 물으면 조건과 영향으로 답한다.
- **질문의 전제가 내 구현과 다르면** "제 구현은 X가 아니라 Y입니다"로 시작한다(가이드 명시).
- **첫 30초에 뼈대를 먼저 친다.** 시간이 끝나면 쓴 만큼 자동 확정되므로, 뼈대만 있어도 핵심은 남는다.

## 유형별 답변 틀

```
[이유] 성공 기준 ~(담당자 발언/수치) 때문에 이 방식을 골랐고, ~안은 ~ 때문에 버렸습니다.
[한계] ~한 경우 ~가 실패할 수 있고, 그러면 ~에 영향이 갑니다.
[다음] ~로 검증하고 ~로 고치겠습니다.
```
재료: `DECISIONS.md`, `DESIGN.md` 4.3

### B. 데이터 흐름으로 구조를 설명하라 (입력 → 출력)
```

[입력] ○○ 형식으로 ○○(파일/API)에서 들어오고, ○○(함수)에서 ~을 검증합니다.
[처리] ○○(함수)가 ~로 변환한 뒤, ○○(함수)에서 [알고리즘]으로 ~을 계산합니다.
[출력] 결과는 ○○ 형식으로 ○○에 저장/표시됩니다.
[예시] 예를 들어 [실제 입력 1건]은 → [중간 값] → [최종 출력]이 됩니다.
[실패] ○단계에서 ~이면 ~로 처리합니다.
```

### C. 어떤 알고리즘을 썼고 왜인가
```
[문제] 이 문제는 [결정 변수]를 정해 [목적]을 최소화/최대화하는 [유형] 문제이고, 제약은 ~입니다.
[방법] [방법 이름]을 썼습니다. 핵심은 ~(2문장)입니다. 복잡도는 O(~)이고, 최적해를 보장합니다/근사입니다.
[이유] 입력 규모 ~와 시간 제한 ~에서 [대안]은 ~ 때문에 맞지 않았습니다.
[검증] 작은 입력 ○건에서 완전 탐색과 일치했고, 제약 위반 0건, 기준 해법 대비 ○% 개선, 실제 규모 ○초입니다.
[한계] ~한 입력에서는 ~이 나빠질 수 있고, 개선하려면 ~를 하겠습니다.
```
재료: `DESIGN.md` 4절 전체, `VERIFICATION.md`

### F. 규모가 커지면 / 확장하려면

## 시간 운영 (문항당 5분)

- 0:00~0:30 — 질문 유형을 고르고(A~K) 틀의 뼈대 줄만 친다
- 0:30~4:00 — 각 줄에 이름·수치·근거를 채운다
- 4:00~5:00 — 빠진 줄이 없는지 보고 제출

## 제출 전 외워 둘 것 (150~170분 사이 HANDOFF.md·DESIGN.md를 읽으며)

- [ ] 입력 형식 1개, 출력 형식 1개
- [ ] 핵심 함수 3~5개 이름과 역할
- [ ] 알고리즘 이름, 복잡도, 최적성, 검증 수치(정답 일치·개선 %·실행 시간)
- [ ] 대표 입력 1건의 여정 (실제 값)
- [ ] 핵심 결정 3개와 버린 대안
- [ ] 실패 조건 3개
- [ ] 롤백·방향 전환이 있었다면 그 신호와 이유
