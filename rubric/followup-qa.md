# 서술형 대비 (6문항 × 5분, AI·복붙 불가)

인지 축이 가장 중요하다고 Cofa Probe 담당자 두 명이 모두 말했고, 코파톤 실측에서는 참가자 전원이 이 축에서 가장 낮았다.
즉 **가장 많이 올릴 수 있는 곳**이다.

## 답변 공식

1. **약점·사실 지목** — 파일·함수 수준으로
2. **이유와 파급** — 왜 그렇게 했고, 언제 실패하며, 무엇이 깨지는가
3. **다음 계획** — 어떻게 검증하고 고칠 것인가

> 코파톤에서는 시스템이 문항마다 모범 답안을 미리 만들어 두고 이 세 단계 구조로 대조했다(참가자 후기).
> Probe는 답변이 실제 구현과 일치하는지도 확인한다(공식 소개).

## 답변 틀 (외워서 그대로 친다)

```
[사실] ○○(파일/함수)는 ~하도록 만들었습니다.
[이유] ~ 때문에 이 방식을 골랐고, ~안은 ~ 때문에 버렸습니다.
[한계] ~한 경우 ~가 실패할 수 있고, 그러면 ~에 영향이 갑니다.
[다음] ~로 검증하고 ~로 고치겠습니다.
```

## 예상 질문 6유형과 답의 재료

| 유형 | 예시 | 답의 재료 |
| --- | --- | --- |
| 구조 선택 | 이 구조를 왜 썼나? 대안은? | `DECISIONS.md` D1~D3 |
| 동작 이해 | 요청이 들어오면 어떤 순서로 처리되나? | `HANDOFF.md` 구조·데이터 흐름 |
| 실패 조건 | 어떤 입력에서 깨지나? 장애가 나면? | `HANDOFF.md` 한계 표, `VERIFICATION.md` 경계 케이스 |
| 확장 | 사용자가 10배가 되면 무엇이 먼저 문제인가? | `DECISIONS.md` 보류 항목 |
| AI 검증 | AI 결과에서 무엇을 확인하고 고쳤나? | `VERIFICATION.md` "잡아낸 오류" |
| 우선순위 | 시간이 더 있으면 무엇부터? | `HANDOFF.md` 다음 할 일 |

## 시간 운영

- 0:00~0:30 — 네 줄 요지([사실][이유][한계][다음])를 먼저 친다
- 0:30~4:00 — 각 줄에 근거(파일명, 수치, 담당자 발언)를 붙인다
- 4:00~5:00 — 빠진 줄이 없는지 보고 제출 (시간 초과 시 쓴 만큼 자동 확정)

## 질문의 전제가 내 구현과 다를 때

"제 구현은 X가 아니라 Y입니다"로 시작하고 내 작업을 설명한다(가이드 명시).

## 리허설 방법 (150~170분 사이)

1. Codex에게 예상 질문 6개만 받는다 (`prompts/codex-prompts.md` §9)
2. 메모장에 AI 없이 5분씩 직접 쓴다
3. Codex에게 "코드와 다른 부분만" 지적받는다
4. 틀린 부분은 `HANDOFF.md`를 다시 읽어 머리에 넣는다
