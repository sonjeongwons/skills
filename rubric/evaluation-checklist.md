# 평가 기준 자가 점검표

Cofa Probe는 결과물·소스 코드·프롬프트와 작업 기록·사후 서술형을 함께 보고 **기술·의도·인지** 3축으로 채점한다.
AI 평가 에이전트(약 20개)가 코드·커밋·대화 로그를 읽고 항목별 근거를 남긴다. 배점은 비공개다.
**로그에 없는 판단은 채점자가 볼 수 없다.** 아래 "증거"가 실제로 남아 있는지 제출 전에 확인한다.

세부 기준 9개는 Cofa Probe 담당자 발언을 정리한 것이다.

## 기술 — AI로 제대로 작동하는 결과물을 만드는가

| 기준 | 증거 (어디에 남나) | 제출 전 확인 |
| --- | --- | --- |
| 산출물을 직접 실행하고 검증 | 터미널 실행 기록, 테스트 결과, `VERIFICATION.md` | [ ] 성공 기준마다 실제 실행 결과가 있다 |
| 유지·확장 가능한 구조 | 기능 단위 커밋, 파일 구조, README 실행법 | [ ] 커밋이 기능 단위로 나뉘어 있다 [ ] 합의에 없는 장치가 없다 |
| 민감정보와 보안 위험 관리 | 코드, `.gitignore`, 보안 체크 | [ ] 키 하드코딩 없음 [ ] 입력 검증 [ ] 개인정보 최소화 |

## 의도 — AI를 원하는 방향으로 이끄는가

| 기준 | 증거 | 제출 전 확인 |
| --- | --- | --- |
| 목표와 제약을 명확히 정의 | 담당자 대화, `INTERVIEW.md`, `AGREEMENT.md` | [ ] 성공 기준이 숫자로, 담당자 확인을 받았다 |
| 작업을 나누고 AI에 위임 | Codex 프롬프트(범위·완료 조건), 커밋 순서 | [ ] "다 해줘"류 프롬프트가 없다 |
| 진행에 따라 방향·우선순위 조정 | `DECISIONS.md` "방향을 바꾼 순간"·"롤백 기록", 롤백 태그, AGREEMENT 버전 이력, 수정 프롬프트 | [ ] 검증 결과로 계획을 바꾼 기록이 1개 이상 있다 [ ] 롤백마다 신호·이유·보존 태그가 있다 |

## 인지 — 결과의 원리와 한계를 이해하는가

| 기준 | 증거 | 제출 전 확인 |
| --- | --- | --- |
| 구조를 선택한 이유 설명 | `DECISIONS.md` (이유·버린 대안), `DESIGN.md` 4.2·4.3 (알고리즘 선택·대안) | [ ] 핵심 결정 3개를 말로 설명할 수 있다 |
| 실제 구성과 동작 방식 이해 | 서술형 답, `DESIGN.md` 2·3절 (데이터 흐름·구성 요소), `HANDOFF.md` 구조 | [ ] 입력부터 출력까지 흐름을 파일·함수 이름으로 말할 수 있다 [ ] 알고리즘을 정식화·복잡도·검증 수치로 말할 수 있다 |
| 한계와 실패 조건 예측 | `HANDOFF.md` 한계 표, `VERIFICATION.md` 경계 케이스, `DESIGN.md` 4.5 | [ ] 실패 조건 3개와 다음 개선을 말할 수 있다 |

## 그 밖에 보는 것

- **비용**: 토큰 사용량이 추적되고 간접 평가에 쓰일 수 있다 → `rubric/cost-control.md`
- **시간 안배**: Codex 응답 시간을 고려한 위임과 시간 배분도 평가 대상(가이드 명시)
- **소통**(코파톤 FDE 트랙에만 있었던 축): 다른 사람·세션이 이어받을 수 있게 일했는가 → `HANDOFF.md`. SK 2차에 이 축이 있는지는 미확인.

## 점수를 깎는 대표 행동 (담당자·후기에서 확인된 것)

- 지시서를 통째로 붙여 넣고 "해줘"
- "구현 다 끝내 놔"로 큰 덩어리 위임 → 고치느라 토큰·시간 소진
- 과설계: 읽기만 하면 되는 API에 쓰기 방어·부하 대비 장치를 넣은 사례
- AI가 "됐다"고 한 것을 직접 확인하지 않고 제출
- 서술형에서 "AI가 그렇게 짰어요"
- 이유·보존 없이 갈아엎기를 반복해 헤맨 흔적만 남기기 (롤백 자체는 감점이 아니다. 기록 없는 롤백이 문제다)
