# 결정 기록

## 언제
- 구조·패턴·라이브러리를 고를 때
- 무언가를 만들지 않기로 할 때 (보류)
- 검증 결과나 담당자 피드백으로 방향을 바꿀 때

## 절차

1. 사람이 말한 결정과 이유를 그대로 받는다. 이유를 지어내지 않는다. 이유가 없으면 묻는다.
2. `DECISIONS.md`에 해당 표의 다음 번호로 한 줄 추가한다.
   - 결정 표: 시각 | 결정 | 이유(근거 문서) | 버린 대안과 이유 | 한계·재검토 조건
   - 보류 표: 항목 | 왜 필요해 보이나 | 왜 지금 안 하나 | 하려면 무엇을
   - 방향 전환 표: 시각 | 무엇을 보고 | 무엇을 바꿨나
3. "한계·재검토 조건"은 "언제 이 결정이 틀리게 되나"를 한 문장으로 쓴다. 예: "동시 사용자가 수백 명을 넘으면 파일 저장 방식은 잠금 문제가 생긴다."
4. 문서 커밋은 기능 커밋과 분리한다: `docs: D3 기록`

## 좋은 예
| D2 | 52분 | 점수 계산을 규칙 기반 함수로 고정 | 합의문 성공 기준 2(같은 입력 같은 결과) | LLM 채점: 재현성 없음 | 규칙이 10개를 넘으면 설정 파일로 분리 필요 |

## 하지 말 것

- "더 좋아서" 같은 이유
