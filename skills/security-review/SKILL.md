# 보안 점검

## 절차

1. **비밀값** — 작업 폴더와 git 이력에서 찾는다.
   ```bash
   git grep -nEi "(api[_-]?key|secret|token|password|passwd|bearer)" -- . ':!*.md'
   git log -p | grep -nEi "(api[_-]?key|secret|token|password)" | head -20
   ls -a | grep -E "^\.env"
   ```
   `.env`가 있으면 `.gitignore`에 있는지 확인한다.

2. **개인정보** — 이름·전화·이메일·주소 등 필드를 찾고, 기능에 꼭 필요한지, 로그·출력·에러 메시지에 찍히는지 본다.

3. **입력 검증** — 사용자 입력이 들어오는 지점(폼, API 파라미터, 파일)마다 타입·길이·형식 검증이 있는지 본다.
   SQL은 파라미터 바인딩인지, HTML 출력은 이스케이프되는지 본다.

4. **외부 전송** — 과제가 요구하지 않는 외부 URL 호출, 텔레메트리, 업로드 코드가 있는지 본다.

5. **보고** — 고치지 말고 표로 보고한다.

| 위치(파일:줄) | 문제 | 위험 | 제안 수정 | 우선순위 |
| --- | --- | --- | --- | --- |

6. 사람이 고칠 항목을 고르면 `delegate-and-verify` 절차로 수정하고, 결과를 `VERIFICATION.md` 보안 점검 칸에 체크한다.
   고치지 않기로 한 항목은 `HANDOFF.md` 한계 표에 적는다.
