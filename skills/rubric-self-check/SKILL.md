# 평가 기준 자가 점검

채점은 AI 평가 에이전트가 코드·커밋·대화 로그·문서를 읽고 항목별 근거를 남기는 방식이다.
**로그와 파일에 없는 판단은 채점자가 볼 수 없다.** 이 스킬은 증거가 남았는지만 본다.

## 참고 파일

- `__KIT_DIR__/rubric/evaluation-checklist.md` — 9개 기준, 증거 위치, 감점 행동

## 절차

1. 점검표를 읽는다.
2. 기준마다 작업 폴더에서 증거를 찾는다.
   - 파일: `AGREEMENT.md`, `INTERVIEW.md`, `DECISIONS.md`, `VERIFICATION.md`, `HANDOFF.md`, README가 정한 필수 문서
   - git: `git log --oneline`, `git log --stat | head -60`
   - 코드: 구조, 키 하드코딩 여부(`security-review` 스킬과 겹치면 그 결과를 쓴다)
3. 보고한다. 증거가 없으면 "없음"으로 쓰고 지어내지 않는다.

| 축 | 기준 | 증거 (파일·커밋) | 상태 | 남은 시간에 할 수 있는 보완 |
| --- | --- | --- | --- | --- |
| 기술 | 직접 실행·검증 |  | 충분 / 약함 / 없음 |  |
| 기술 | 유지·확장 가능한 구조 |  |  |  |
| 기술 | 민감정보·보안 |  |  |  |
| 의도 | 목표·제약 정의 |  |  |  |
| 의도 | 작업 분해·위임 |  |  |  |
| 의도 | 방향·우선순위 조정 |  |  |  |
| 인지 | 구조 선택 이유 |  |  |  |
| 인지 | 구성·동작 이해 |  |  |  |
| 인지 | 한계·실패 조건 |  |  |  |

   롤백이 있었다면 "방향·우선순위 조정" 기준의 증거로 본다: `DECISIONS.md` 롤백 기록의 신호·이유가 비어 있지 않은지, 태그(`git tag -l 'rollback-*'`)와 맞는지, 이전 문서가 지워지지 않고 "대체됨"으로 남았는지 확인한다.
4. 보완 제안은 **실제로 한 일을 기록하는 것**에 한정한다. 하지 않은 검증이나 결정을 문서에 만들어 넣지 않는다.
   예: "VERIFICATION.md에 이미 실행한 경계 케이스 2개가 빠져 있음 → 실행 기록을 옮겨 적기"
5. 우선순위 3개를 고른다. 인지 축(이유·한계)이 비어 있으면 가장 먼저 채운다.
