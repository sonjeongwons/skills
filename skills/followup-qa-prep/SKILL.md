# 서술형 대비

## 원칙
서술형은 AI·복사·붙여넣기 없이 사람이 직접 답한다. 이 절차는 **질문과 대조만** 하고 모범 답안을 쓰지 않는다.
답변 공식과 예상 질문 유형은 `__KIT_DIR__/rubric/followup-qa.md`를 참고한다.

## 절차

1. **질문 6개 생성** — 실제 코드, git 이력, `DECISIONS.md`, `HANDOFF.md`를 보고 다음 유형을 하나씩 섞는다.
   - 구조 선택 이유와 대안
   - 특정 기능의 실제 동작 순서 (파일·함수 단위)
   - 실패 조건 (어떤 입력·상황에서 깨지나)
   - 확장 시 먼저 문제가 되는 곳
   - AI 결과에서 무엇을 검증하고 고쳤나
   - 시간이 더 있으면 무엇부터
   일부 질문에는 **실제 구현과 다른 전제**를 하나 섞는다(예: 실제로는 파일 저장인데 "DB를 왜 골랐나"). 사람이 전제 오류를 짚는 연습을 하기 위해서다.
   질문만 출력하고 답은 출력하지 않는다.

2. **대조** — 사람이 답을 주면, 실제 코드·문서와 **다른 부분만** 파일:줄 근거로 지적한다.
   맞는 부분은 "일치"라고만 쓴다. 고쳐 쓴 답안을 제시하지 않는다.

3. **약한 곳 목록** — 대조 결과로 사람이 다시 읽어야 할 파일·결정을 3개 이내로 알려준다.

## 사람이 쓸 답 형식 (참고용으로만 보여준다)
```
[사실] ○○(파일/함수)는 ~하도록 만들었습니다.
[이유] ~ 때문에 이 방식을 골랐고, ~안은 ~ 때문에 버렸습니다.
[한계] ~한 경우 ~가 실패할 수 있고, 그러면 ~에 영향이 갑니다.
[다음] ~로 검증하고 ~로 고치겠습니다.
```
