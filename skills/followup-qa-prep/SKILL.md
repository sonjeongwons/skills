# 서술형 대비

## 원칙
서술형은 AI·복사·붙여넣기 없이 사람이 직접 답한다. 이 절차는 **질문과 대조만** 하고 모범 답안을 쓰지 않는다.
유형별 답변 틀(A~K)은 `__KIT_DIR__/rubric/followup-qa.md`에 있다.

## 절차

0. **재료 점검** — `DESIGN.md` 2절(데이터 흐름)과 4절(알고리즘)이 실제 코드와 일치하는지 먼저 본다. 다르거나 비어 있으면 질문을 만들기 전에 사람에게 알리고, 사람이 동의하면 **코드에 있는 사실만으로** 채운다.

1. **질문 6개 생성** — 실제 코드, git 이력, `DESIGN.md`, `DECISIONS.md`, `HANDOFF.md`를 보고 아래 유형을 섞는다. 과제에 알고리즘이 있으면 B와 C는 반드시 넣는다.
   | 코드 | 유형 | 예 |
   | --- | --- | --- |
   | A | 선택 이유 | 이 구조/라이브러리를 왜 썼나, 대안은 |
   | B | 데이터 흐름 | 입력부터 출력까지 흐름으로 구조를 설명하라 |
   | C | 알고리즘 | 어떤 알고리즘을 썼고 왜인가, 복잡도·최적성·검증은 |
   | D | 동작 | 특정 기능이 호출되면 어떤 순서로 처리되나 |
   | E | 실패 | 어떤 입력에서 실패하나, 장애가 나면 |
   | F | 확장 | 데이터·사용자가 10배가 되면 무엇이 먼저 문제인가 |
   | G | AI 활용 | AI에 무엇을 맡겼고 무엇을 직접 검증·수정했나 |
   | H | 방향 전환 | 중간에 왜 바꿨나 |
   | I | 사용자 가치 | 담당자의 문제를 어떻게 푸나, 성공 기준은 어떻게 확인했나 |
   | J | 보안·데이터 | 민감 정보와 입력을 어떻게 다뤘나 |
   | K | 우선순위 | 시간이 더 있으면 무엇부터 |
   한 문항에는 **실제 구현과 다른 전제**를 하나 섞는다(예: 실제로는 탐욕 알고리즘인데 "DP의 점화식을 설명하라"). 전제 오류를 짚는 연습이다.
   질문 앞에 유형 코드만 붙이고, 답은 출력하지 않는다.

2. **대조** — 사람이 답을 주면, 실제 코드·문서와 **다른 부분만** 파일:줄 근거로 지적한다.
   - 이름(파일·함수·형식)이 틀렸는지, 순서가 틀렸는지, 수치가 틀렸는지, 빠진 단계가 있는지
   - 맞는 부분은 "일치"라고만 쓴다. 고쳐 쓴 답안을 제시하지 않는다.

3. **약한 곳 목록** — 대조 결과로 사람이 다시 읽어야 할 파일·함수·결정을 3개 이내로 알려준다.

4. **외울 목록** — 아래를 코드에서 찾아 한 화면으로 보여준다(답안이 아니라 사실 목록).
   - 입력 형식 / 출력 형식
   - 핵심 함수 3~5개와 역할
   - 알고리즘 이름·복잡도·최적성·검증 수치
   - 대표 입력 1건의 여정 (실제 값)
