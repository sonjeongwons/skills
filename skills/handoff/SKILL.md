# 인계 문서 만들기

## 언제
- Codex 대화가 길어져 응답이 느려지거나 맥락을 놓치기 시작할 때 → 갱신 후 새 세션
- 큰 단계가 끝났을 때 (v0 완성, 검증 완료)
- 제출 직전 (최종본)

## 절차

1. **사실 수집** — 추측하지 않고 다음에서만 가져온다.
   - `git log --oneline`과 `git status`
   - `AGREEMENT.md`(성공 기준), `DECISIONS.md`, `VERIFICATION.md`
   - 실제 파일 구조 (`ls`, 핵심 파일 열람)

2. **HANDOFF.md 갱신** — 템플릿의 모든 칸을 채운다.
   - 현재 위치: 현재 단계, 합의 버전, 롤백 이력(`DECISIONS.md` 롤백 기록과 `git tag -l 'rollback-*'`로 확인).
   - 현재 상태: 기능별 동작/부분/미구현 + 검증 근거. 검증 기록이 없으면 "미검증"이라고 쓴다.
   - 실행 방법: 실제로 실행해 본 명령만.
   - 구조: 핵심 파일 3~7개와 역할, 데이터 흐름 한 줄.
   - 핵심 결정 3개: `DECISIONS.md`에서 고른다.
   - 한계와 실패 조건: 언제 실패하나 / 영향 / 다음 개선.
   - 다음 할 일: 우선순위 순 3개.

3. **자기 점검** — 이 문서만 읽은 사람이 10분 안에 실행하고 다음 일을 시작할 수 있는가? 아니면 빠진 것을 채운다.

4. **커밋** — `docs: handoff 갱신 (<단계>)`

5. **새 세션 시작 문구** — 사람에게 다음 문구를 돌려준다.
   ```
   HANDOFF.md, AGREEMENT.md, DECISIONS.md를 읽고 현재 상태를 3줄로 요약해.
   그다음 '다음 사람이 할 일' 1번만 진행해. 범위 밖은 건드리지 마.
   ```

## 하지 말 것
- 검증하지 않은 기능을 "동작"으로 쓰기
- 한계를 비우기. 한계가 없는 결과물은 없다. 서술형 질문의 재료가 된다.
