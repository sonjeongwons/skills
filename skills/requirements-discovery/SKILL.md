# 요구 발굴과 합의

## 언제
- 과제를 막 받았을 때 (구현 전)
- 담당자 피드백으로 범위가 흔들릴 때

## 절차

1. **지시서 구조화** — README(과제 지시서)를 읽고 세 목록으로 나눈다.
   - 확정된 요건 (지시서에 명시)
   - 담당자에게 확인할 것 (모호하거나 빠진 것)
   - 필수 제출물과 파일명
   지시서에 없는 내용은 추측하지 않고 "확인 필요"로 둔다. 이 단계에서 코드는 만들지 않는다.

2. **인터뷰 질문 준비** — 확인할 것을 다음 순서로 질문 초안으로 바꾼다.
   범위 → 에피소드 → 현재 방식 → 정량화 → 당사자 → 경계 → 합의.
   질문은 하나에 하나만 묻고, 해법 단어('AI', '자동화')는 처음에 쓰지 않는다.
   **질문은 사람이 직접 담당자에게 보낸다.** 에이전트는 초안만 만든다.

3. **기록** — 사람이 붙여 준 담당자 답을 `INTERVIEW.md` 표에 한 줄씩 정리하고,
   "설계에 미치는 영향" 칸을 채운다. 지시서와 다른 점은 별도 목록에 둔다.

4. **합의문 초안** — `AGREEMENT.md`를 채운다.
   - 성공 기준은 숫자 / 현재 값 / 측정 방법으로. 형용사("빠르게") 금지.
   - "만들지 않을 것"을 최소 1개.
   - 담당자 확인을 받기 전에는 상단에 "초안"이라고 쓴다.

5. **확인 요청 문안** — 담당자에게 보낼 3~5줄 요약을 만든다.
   "제가 이해한 내용입니다: … 성공 기준은 …입니다. 맞는지 확인 부탁드립니다."

## 출력
- 확인할 질문 목록(우선순위 순), 갱신된 `INTERVIEW.md`, `AGREEMENT.md` 초안, 확인 요청 문안

## 하지 말 것
- 담당자 답을 지어내기
- 인터뷰가 끝나기 전에 구현 시작
- "할 일을 순서대로 알려 달라"는 식의 질문 초안 만들기
