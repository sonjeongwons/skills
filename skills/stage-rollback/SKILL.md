# 단계 롤백

단계는 앞뒤로 움직인다. 롤백은 감점이 아니라 "진행에 따라 방향과 우선순위 조정"의 증거가 될 수 있지만, **보존과 기록이 없으면 그냥 헤맨 것으로 보인다.**

## 참고 파일
- 롤백 유형·시간 한계·절차: `__KIT_DIR__/playbook/09-rollback.md`
- 목표 단계의 규칙: `__KIT_DIR__/playbook/0N-*.md` ("다시 이 단계로 돌아올 때" 절)

## 절차

1. **신호와 시간 확인** — 사람에게 무엇을 보고 롤백하려는지, 경과 시간이 몇 분인지 확인한다. 모르면 묻는다.

2. **유형 제안** — `09-rollback.md`의 표에서 유형(R1 재인터뷰, R2 재합의, R3 재설계, R4 기능 되돌리기, R5 갈아엎기)과 목표 단계를 제안한다.
   경과 시간이 그 유형의 한계를 넘으면 그렇게 알리고 대안(범위 축소, 한계로 기록)을 함께 제시한다. **결정은 사람이 한다.**

3. **보존** — 결정이 나면 무엇이든 지우거나 되돌리기 전에 실행한다.
   ```bash
   git add -A
   git commit -m "wip: 롤백 전 상태 보존 (R<유형> <이유 요약>)" --allow-empty
   git tag rollback-<번호>-before
   # R3·R5면 추가로:
   git branch attempt-<번호>
   ```
   번호는 `git tag -l 'rollback-*'`로 다음 번호를 정한다.

4. **기록** — `DECISIONS.md` "롤백 기록" 표에 한 줄. 사람이 말한 신호와 이유만 적는다.
   대체되는 이전 결정 행에는 "대체됨 → R<번호>"를 덧붙인다(지우지 않는다).

5. **문서 버전업** — 지우지 않고 쌓는다.
   - `AGREEMENT.md`: R1·R2·R5면 버전을 올리고(v1→v2) 변경 이력에 한 줄, 바뀐 항목은 "대체됨(v2)"
   - `INTERVIEW.md`: R1·R5면 "## N회차 (시각, R<번호>)"를 새로 열고 틀렸던 가정을 첫 줄에
   - `VERIFICATION.md`: 바뀌는 코드에 걸린 검증 행을 "재검증 필요 (R<번호>)"로
   - `HANDOFF.md`: "현재 위치"의 단계·합의 버전·롤백 이력 갱신

6. **코드 처리** (사람 승인 후)
   - R4: `git revert <커밋>` — 이력을 남기며 되돌린다
   - 특정 파일만 이전으로: `git checkout <태그 또는 커밋> -- <경로>`
   - R3·R5: 새 구조를 만들고, 버리는 파일은 `git rm`으로 정리해 커밋
   - 금지: `git reset --hard`, `git checkout .`, `git clean -fd`, 태그 없는 삭제

7. **시간 재배분** — 남은 시간을 목표 단계부터 다시 나눈다. 70분(v0), 125분(새 기능 중단), 170분(제출 시작) 선은 움직이지 않는다. 시간이 모자라면 줄일 범위를 2개 이내로 제안한다.

8. **보고**

```
롤백 R<번호> (<유형>): <현재 단계> → <목표 단계>
보존: 태그 rollback-<번호>-before [브랜치 attempt-<번호>]
문서: AGREEMENT v_ / INTERVIEW _회차 / VERIFICATION 재검증 필요 _행 / HANDOFF 갱신
남은 시간 배분: …
다음 행동: <목표 단계 플레이북의 첫 할 일>
```

## 하지 말 것
- 사람 결정 없이 롤백 시작
- 보존(커밋+태그) 전에 파일 삭제·되돌리기
- 문서의 이전 내용을 지우고 새로 쓰기
- 같은 롤백을 이유 없이 반복 — 두 번째면 범위 축소를 먼저 제안
