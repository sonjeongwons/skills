# 08. 서술형 (대기 약 5분 + 6문항 × 5분)

## 규칙 (가이드)
- 제출물과 작업 기록을 바탕으로 문항이 만들어진다. 준비 대기는 최대 10분.
- 문항당 5분. 첫 문항은 "문제 풀기"를 누를 때, 다음 문항은 직전 답 제출 순간부터 시간이 흐른다.
- AI 사용 금지, 복사·붙여넣기 불가, 이전 문항 이동 불가. 시간이 끝나면 쓴 만큼 자동 확정.
- 14:00이 넘으면 모든 응시가 끝난다.

## 답변 공식 (3단)

1. **약점·사실 지목**: 파일·함수 수준으로 구체적으로. "`api/score.py`의 `calc()`는 ~를 고정 규칙으로 계산합니다."
2. **이유와 파급**: 왜 그렇게 했고, 언제 실패하며, 실패하면 무엇이 깨지는가.
3. **다음 계획**: 어떻게 검증하고 고칠 것인가.

## 시간 쓰는 법
- 첫 30초: 세 단계 요지를 한 줄씩 먼저 친다. 시간이 끝나도 핵심은 남는다.
- 다음 3분: 각 줄에 근거(파일명, 수치, 담당자 발언)를 붙인다.
- 마지막 1분: 오타보다 빠진 단계가 없는지 확인 후 제출.

## 질문의 전제가 틀렸을 때
가이드: 질문의 전제와 실제 구현이 다르면 차이를 밝히고 본인의 작업을 설명한다.
→ "제 구현은 X가 아니라 Y입니다. 이유는 ~입니다."로 시작한다.

## 자주 나올 질문 유형 (답변 틀은 `rubric/followup-qa.md` A~K)
실제 응시에서 "어떤 알고리즘을 썼나", "데이터 입력부터 흐름을 통해 구조를 설명하라" 외에도 여러 유형이 나왔다.

| 코드 | 유형 | 예 | 재료 |
| --- | --- | --- | --- |
| A | 선택 이유 | 이 구조·라이브러리를 왜 골랐나? 대안은? | `DECISIONS.md` |
| B | 데이터 흐름 | 입력부터 출력까지 흐름으로 구조를 설명하라 | `DESIGN.md` 2·3절 |
| C | 알고리즘 | 어떤 알고리즘을 썼고 왜인가? 복잡도·최적성·검증은? | `DESIGN.md` 4절 |
| D | 동작 | 이 기능은 어떤 순서로 처리되나? | 코드, `DESIGN.md` 2절 |
| E | 실패 | 어떤 입력·상황에서 실패하나? 장애가 나면? | `HANDOFF.md`, `DESIGN.md` 4.5 |
| F | 확장 | 10배가 되면 무엇이 먼저 문제인가? | `DECISIONS.md` 보류, 복잡도 |
| G | AI 활용 | AI에 무엇을 맡기고 무엇을 직접 확인·수정했나? | `VERIFICATION.md` |
| H | 방향 전환 | 중간에 왜 바꿨나? | 롤백 기록 |
| I | 사용자 가치 | 담당자의 문제를 어떻게 푸나? | `INTERVIEW.md`, `AGREEMENT.md` |
| J | 보안·데이터 | 민감 정보와 입력을 어떻게 다뤘나? | 보안 점검 |
| K | 우선순위 | 시간이 더 있으면 무엇부터? | `HANDOFF.md` 다음 할 일 |
