# 03. 서면 합의 (30~42분)

## 목표
이해한 문제와 성공 기준을 담당자에게 확인받아 문서로 고정한다. 이후 모든 위임은 이 문서를 기준으로 한다.

## 할 일
- [ ] `AGREEMENT.md` 작성: 이해한 문제 / 병목 / 성공 기준(숫자·현재 값·측정 방법) / 만들 것·안 만들 것 / 제약
- [ ] 담당자에게 요약을 보내 확인받기: "제가 이해한 내용을 정리했습니다. 맞는지 확인해 주세요."
- [ ] 담당자 답에 따라 수정하고, 확인 시각을 문서 상단에 적기
- [ ] `AGENTS.md` 점검: 과제 특성에 맞게 한두 줄 보완 (예: 사용 언어, 실행 포트)
- [ ] 첫 커밋: `git add -A && git commit -m "docs: 합의문과 작업 규칙"`

## 종료 조건
- 담당자가 확인한 성공 기준이 숫자로 적혀 있다.
- "만들지 않을 것"이 최소 1개 적혀 있다.

## 남길 증거 → 평가 기준
- `AGREEMENT.md` + 담당자 확인 대화 → 의도: 목표와 제약을 명확히 정의
- "만들지 않을 것" → 기술: 과설계 방지 / 인지: 범위 판단의 이유

## 하지 말 것
- 합의 없이 범위 확장.
- 성공 기준을 형용사로 쓰기("빠르게", "쉽게"). 숫자나 확인 가능한 동작으로 쓴다.

## 되돌아가는 신호
- 담당자가 합의 내용을 확인해 주지 않거나, 확인 중에 새로운 사실이 나온다 → **2. 문제 발굴** (R1)

## 다시 이 단계로 돌아올 때 (R2 재합의)
- `AGREEMENT.md` 버전을 올리고(v1 → v2) 변경 이력에 이유를 쓴다. 이전 기준은 지우지 않고 "대체됨"으로 둔다.
- 줄어든 범위를 담당자에게 확인받는다: "시간상 1·2번 기준을 먼저 완성하고, 3번은 다음 단계로 두려 합니다. 괜찮을까요?"
