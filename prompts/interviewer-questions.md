# 업무 담당자 에이전트 인터뷰

담당자 에이전트는 한 번에 다 알려주지 않고, 물어본 것만 하나씩 답하도록 설계돼 있다.
사소한 질문부터 정보를 모아 깊은 질문으로 가는 사람이 점수를 잘 받는다.
처음 3분은 'AI', '자동화' 같은 해법 단어를 쓰지 않는다. 답은 `INTERVIEW.md`에 바로 적는다.

| 순서 | 물을 것 | 예시 질문 |
| --- | --- | --- |
| 1. 범위 | 담당자가 답할 수 있는 범위 | "안녕하세요, 이번 과제를 맡은 ○○입니다. 제가 어떤 것들을 여쭤보면 될까요?" |
| 2. 에피소드 | 최근 실제로 있었던 일 | "가장 최근에 이 문제로 곤란했던 상황을 구체적으로 말씀해 주실 수 있나요?" |
| 3. 현재 방식 | 지금은 어떻게 해결하나 | "지금은 누가, 어떤 도구로, 어떤 순서로 처리하시나요?" |
| 4. 정량화 | 빈도·시간·비용·실패율 | "한 달에 몇 번 생기고, 한 번에 얼마나 걸리나요? 실수는 얼마나 나나요?" |
| 5. 당사자 | 누가 쓰고 누가 판단하나 | "이 기능을 직접 쓰는 사람은 누구고, 결과를 확인하는 사람은 누구인가요?" |
| 6. 경계 | 하지 말아야 할 것·제약 | "이번 버전에서 꼭 없어도 되는 것은 무엇인가요? 다루면 안 되는 데이터가 있나요?" |
| 7. 합의 | 성공 기준 확인 | "제가 이해한 내용을 정리했습니다. 성공 기준이 이 세 가지가 맞는지 확인해 주세요." |

## 구현 중·후 대화

| 시점 | 예시 |
| --- | --- |
| v0 완성 | "가장 작은 버전이 동작합니다. [핵심 흐름]을 이렇게 처리하는데, 실제로 쓰실 때 어색한 부분이 있을까요?" |
| 선택이 필요할 때 | "[A]와 [B] 중 무엇이 더 중요하세요? 시간상 하나를 먼저 하려고 합니다." |
| 최종 보고 | "성공 기준별 결과입니다: 1번 통과, 2번 통과, 3번은 [한계]. 남은 부분은 이렇게 개선할 계획입니다." |

## 하지 말 것

- "지금 해야 할 일을 하나, 둘, 셋, 넷으로 알려주세요." — 막혀 있고 평가도 나빠진다.
- "어떻게 만들면 될까요?" — 해법은 내가 정한다. 담당자에게는 문제와 기준을 묻는다.
- 같은 질문을 말만 바꿔 반복하기 — README 범위 밖 정보는 대부분 나오지 않는다.
